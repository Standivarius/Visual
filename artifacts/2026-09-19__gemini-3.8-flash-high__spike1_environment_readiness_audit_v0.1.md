## Minimum required installs

Install Visual Studio 2022 Build Tools (or Visual Studio 2022) with:

- **Desktop development with C++** workload (`Microsoft.VisualStudio.Workload.VCTools`).
- **MSVC v143 C++ x64/x86 build tools** (`Microsoft.VisualStudio.Component.VC.Tools.x86.x64`).
- A modern **Windows 10/11 SDK** containing the required Win32, D3D11, DXGI, Windows Runtime metadata, and Windows Graphics Capture interop headers.
- **CMake** support. This can be installed as the Visual Studio CMake component or separately.

Ninja is optional because CMake can use a Visual Studio/MSBuild generator. vcpkg is not required because Spike 1 should use only Windows SDK/MSVC facilities.

## Post-install verification

1. Verify MSVC with `vswhere.exe -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64`.
2. Verify installed SDK headers/libs including `d3d11.h`, `dxgi1_2.h`, `windows.graphics.capture.interop.h`, Windows Runtime metadata/C++/WinRT support, `d3d11.lib`, `dxgi.lib`, and `windowsapp.lib` where applicable.
3. Verify `cmake --version`.
4. Re-run display enumeration from the actual interactive user desktop and confirm both physical monitors, geometry, refresh, DPI/scaling, orientation, and primary display.
5. Run a minimal C++/WinRT + D3D11 configure/build smoke test before starting Spike 1 implementation.

## Rationale

The machine is not ready to build the native Windows graphics spike because the compiler toolchain, Windows SDK, and CMake are absent. The operating system, GPU driver, Git, PowerShell, winget, repository, and Antigravity/Gemini delegation path are available. The monitor evidence collected from the background bridge context is not suitable for certifying the actual dual-monitor environment and must be repeated interactively after the toolchain is installed.
